# ADR 0008: Independent breaker contact and racking state

Date: 23 October 2026. Status: implemented locally in the generic session, synthetic fixture and site `construction-2026-10-23.2`. Owner answers26/29 require separate Open/Close and Rack in/out actions for drawing-shown removable breakers, while later answers select the baseline and local SW411 rules. Represent contact and racking as independent nullable fields on one asset, behind the existing `SimulationSession` seam, so an action changes one field without inventing the other.

Composite position strings would multiply partial-state combinations; a second visible rack-contact asset would introduce a separate identity for part of the same breaker. A private mechanism module instead evaluates the declared main pair and action restrictions, preserving separate earth relationships. Racking requires known Open; contact actions require known Rack in. Other unresolved interlock reviews still apply. Independent null values remain unconfirmed in connectivity, inspection, history and scenario validation.

Extend ADR0007's format1-only decision for new structured-state models: use a new format2 envelope while retaining the format1 reader and format1 saving for legacy-only models. Historical snapshots, their original states and fingerprints remain unchanged; do not migrate them or fill Rack in defaults. Changes to a site model still require a new immutable model version and owner acceptance remains separate. Preserved `construction-2026-10-23.1` contains no racking-state conversion; `.2` converts only the119 audit/owner-selected mechanisms and applies the separately recorded starting selections. Other interlock reviews remain mandatory; only the24 specifically selected SW411 line-earth reviews are resolved by answer37.

## Extension: removable motor contactors

Owner answers50–51 on23October2026 select independent contact/racking state for all24 Forward/Reverse contactors and explicitly select Open/Rack in as their baseline. Preserve `kind: 'contactor'`; a contactor does not become a breaker to reuse its mechanism. Add a distinct optional `removableContactor: { mainPair }` annotation and share the private mechanism evaluation and intrinsic guards with removable breakers. Reject annotations on the wrong asset kind and reject both annotations on one asset. Existing breaker declarations and historical format1/format2 snapshots remain unchanged.

The selected contactor profile additionally requires own maintenance earth Open before Rack in, opposite contactor Open and maintenance earth Open before Close, and both contactors Open/Rack out before Earth Close. Unknown prerequisites block. Only the key/door/inching sequences explicitly listed in answer49 are deferred. These local rules and baseline selections are separate model evidence; the generic mechanism itself does not supply site permissions. Exact decisions are recorded in `drawing-review/supplemental/owner-interlocks-review.md`.

## Extension: removable disconnectors

Preserve disconnector kind and use a distinct optional `removableDisconnector: { mainPair }` annotation.
