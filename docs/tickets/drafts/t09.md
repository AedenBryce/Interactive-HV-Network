[Specification #1](https://github.com/AedenBryce/Interactive-HV-Network/issues/1)

## What to build

Download a scenario file containing its original model snapshot and reopen it against a matching model version to reproduce the same scenario.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] Scenario files contain the complete original network-model snapshot, model version, selected device states and source availability.
- [ ] Save/load controls use the simulation-session boundary and file adapters; the original PDFs and a separate historical-model file are not needed.
- [ ] Loading a compatible scenario reproduces its states, source/earth connectivity, conflicts and inspection information, including provisional evidence/review status and equipment-position data.
- [ ] Validate structure, model identity and asset/state references before replacing the active session; malformed files leave the existing session unchanged and show a clear error.
- [ ] Model versions identify immutable model packages; document that relevant model/baseline changes require a new version, without adding automatic scenario migration.
- [ ] Tests cover a full round trip through the session and a browser file save/load interaction. Persisting the complete action history is not required.
