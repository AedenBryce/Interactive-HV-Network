## What to build

Load a model with unresolved connections, states or source information, inspect its evidence and see unconfirmed results precisely where those gaps matter.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] Model and display supported facts, provisional interpretations, unresolved questions and owner-confirmed resolutions without treating those statuses as interchangeable.
- [ ] Asset/connection inspection exposes available drawing references and linked review records; a best guess is explicitly labelled unconfirmed.
- [ ] Results depending on an unresolved connection, device state or source availability remain unconfirmed rather than silently defaulting to open, disconnected or unavailable.
- [ ] A known source path remains identifiable when additional possible routes are unresolved; source and earth uncertainty are evaluated separately.
- [ ] An off-page boundary without confirmed coverage is shown as an unconfirmed connection rather than silently removed or declared disconnected.
- [ ] Session tests and a browser check demonstrate an unknown route, an unknown source, an uncertain earth connection and an unaffected known supply path.
