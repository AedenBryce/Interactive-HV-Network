[Specification #1](https://github.com/AedenBryce/Interactive-HV-Network/issues/1)

## What to build

Toggle sources and switch alternative routes, then inspect affected assets and trace the supply paths that remain available.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] A synthetic model demonstrates multiple enabled sources, a bus tie, alternate paths and a loop; source availability is exposed as a session action and UI control.
- [ ] Opening one path leaves an asset connected when an alternative enabled-source path remains; disabling a source recomputes the same model without changing unrelated device states.
- [ ] Selecting an asset shows explanatory source paths; a switching/source action lists affected assets and highlights changed and remaining paths.
- [ ] An unchanged connectivity classification is distinguishable from a changed supply route where the available explanation changes.
- [ ] Session tests cover single-path loss, surviving alternate supply, bus-tie operation, source loss and loop handling; a browser check exercises source control and path inspection.
