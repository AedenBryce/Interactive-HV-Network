## What to build

Move between network overview and detailed views with pan/zoom while retaining asset identity, session state and connectivity explanations.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] Represent overview/detail organisation separately from authoritative electrical connections and device states.
- [ ] Provide pan/zoom and navigation to individual areas without losing the active session.
- [ ] Asset selection, source connectivity and impact/path information refer to the same assets and session in every view.
- [ ] Cross-area connections remain identifiable when their endpoints are displayed in different views; drawing-page boundaries do not sever topology.
- [ ] Browser checks demonstrate cross-view navigation, selection, switching and inspection; session tests remain the primary rule tests.
- [ ] Do not add a network-editing interface.
