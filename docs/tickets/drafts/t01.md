## Parent

[Specification #1](https://github.com/AedenBryce/Interactive-HV-Network/issues/1)

## What to build

Run the local application, select a breaker in an explicitly synthetic source-to-LV-bus network, switch it, and see the resulting source connectivity.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] The local browser application starts with documented development commands and a clearly identified synthetic model; it is not presented as the actual network.
- [ ] A versioned model identifies assets, terminals, connections, source attachments, a transformer relationship, an LV bus endpoint, supported states and a starting configuration independently of diagram coordinates.
- [ ] Users see a single-line diagram, select a breaker, inspect its identity/state, change between the fixture's supported states, and see updated connectivity on the affected path.
- [ ] The simulation-session interface owns state changes and returns coherent observable results; UI components do not implement a second connectivity engine.
- [ ] Malformed model structure, missing references and unsupported state requests produce clear errors instead of silently dropping data or replacing a valid session.
- [ ] Meaningful tests through the session boundary and a small browser check demonstrate the complete switching behaviour without testing traversal internals.
- [ ] Choose and document the initial application/tooling decisions needed for this slice without adding a backend, live equipment integration, PDF runtime requirement or network editor.
