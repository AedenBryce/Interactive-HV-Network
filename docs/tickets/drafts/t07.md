## What to build

Follow accepted session actions, undo device/source changes and reset the network to its starting configuration.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] Show accepted device and source actions in session history with their resulting state changes.
- [ ] Undo restores the preceding accepted states and recomputes connectivity/explanations; blocked actions do not become accepted history entries.
- [ ] Reset restores both starting device states and starting source availability, then recomputes the result.
- [ ] History operates on the session's model and state rather than an independent UI simulation; unsupported history operations leave the session intact.
- [ ] Session tests and browser checks cover switching, source toggling, a blocked action, undo and reset against a clearly identified synthetic starting configuration.
