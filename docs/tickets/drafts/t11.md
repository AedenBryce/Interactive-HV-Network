## What to build

Inspect a source-referenced SW411 model and its feeder/interface points, with current ambiguities visible in the running application.

Scope: SW411 main HV switchroom and overview reconciliation.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] Review the detailed main-switchroom SLD, the current two-sheet OPF overview and the earlier distribution overview visually; retain document/revision/page/location references for represented assets and connections.
- [ ] Render SW411 bus sections, incomers, bus tie, earth devices and outgoing feeder/interface points using stable identities and recorded drawing aliases.
- [ ] Retain existing source/commissioning, feeder-identity and earthing-interlock questions as unconfirmed review records; do not resolve drawing precedence from dates or labels alone.
- [ ] Affected unresolved interlocks disable controls; provisional connections/starting states produce visible uncertainty instead of an invented accepted lineup.
- [ ] Start a coverage register assigning every supplied document to a network area, a duplicate/reference relationship, or a documented review disposition; assignment is not a declaration that its topology has been reviewed.
- [ ] Demonstrate the area in the running diagram with asset/evidence inspection and supported scenario actions; validate structure and add evidence-based model regression checks without claiming owner acceptance.
