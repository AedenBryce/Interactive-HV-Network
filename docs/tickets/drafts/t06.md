## What to build

Use synthetic multi-position equipment and a multi-winding transformer whose displayed connections and interlock results follow explicit model data.

Implement this as a complete model/session/UI/test slice using the approved simulation-session boundary in the parent specification. Synthetic fixtures must be explicitly identified. Real-network interpretations require source evidence or owner confirmation; unresolved facts remain labelled unconfirmed. Successful software tests do not constitute model acceptance.

## Acceptance criteria

- [ ] Equipment can declare supported positions and terminal-to-terminal relationships per position, instead of being forced into a universal open/closed representation.
- [ ] A synthetic multi-position device and multi-winding transformer demonstrate the needed model expressiveness through visible controls and connectivity results.
- [ ] Transformer reachability and any modelled backfeed relationship are explicit; do not infer universal behaviour from the device name, nominal voltage or generic symbol.
- [ ] Position changes pass through the same interlock and session validation as other switching; unsupported positions fail without mutating the scenario.
- [ ] The diagram identifies the selected position and represents the corresponding connections consistently.
- [ ] Session tests and a browser check cover the fixture's positions, winding relationships and blocked/unsupported changes; the synthetic rules are not presented as site facts.
